# 計測計画 / 実験設計（A/C ハイブリッド改修）

作成: 2026-09-05 / 対象: `prototype/ac-hybrid-top`
前提となる正本: `docs/MEASUREMENT_SPEC.md`（イベント定義の SSOT。**こちらが優先**）

この文書は「新しい計測基盤を作る計画」ではない。
**既存の GA4 基盤（`G-ZFSK3YRNJL`）で、今回の改修の効果をどう読むか**を決めるもの。

---

## 1. 既存基盤で足りているもの（新規実装は不要）

| 必要なこと | 既存の手当て |
|---|---|
| CTA クリックの位置別集計 | `cta_click` の `cta_position`。今回 `price` を語彙に追加 |
| どのページで押されたか | `source_page`（`body[data-page]`） |
| 遷移をまたぐイベントの取りこぼし | `sessionStorage` に預けて遷移先で送る仕組みが実装済み |
| 見積りツールの離脱段階 | `estimator_view` / `_start` / `_step` / `_complete` |
| 問い合わせ完了 | `generate_lead`（Lead API の保存確定時のみ） |
| 作品別の反応 | `work_id` / `work_name` / `work_position` / `cta_action` |
| スクロール到達 | GA4 Enhanced Measurement の `scroll`（90%） |

**新規イベントは1つも追加しない。** 重複イベントを作らないため。
今回追加したのは `data-cta-position` 属性の付与のみで、これは既存の送信経路に乗る。

### 今回の改修で新しく区別できるようになるもの

| `cta_position` | 対応する要素 | 改修前 |
|---|---|---|
| `header` | 追従ヘッダーの「無料相談」 | **狭い画面では存在しなかった** |
| `hero` | Hero の「無料で相談する」「3分で概算費用」 | Hero CTA は `WORKSを見る` が主だった |
| `price` | 料金セクション末尾 | **セクションごと存在しなかった** |
| `final` | 最終CTA | 位置属性が無く `body` に落ちていた |
| `works` | 作品カードのデモ / 制作プロセス | 同上 |

---

## 2. 見るべき指標（優先順）

1. **`generate_lead` の件数**（＝実際の問い合わせ）。最終目的関数
2. **`cta_click` (`cta_type=contact`) の `cta_position` 別内訳**
   ここが今回の設計判断そのもの。特に狭い画面での `header` の比率
3. **`estimator_complete` → `estimate_to_contact` の遷移率**
   Secondary CTA が Primary へ橋渡しできているか
4. **`cta_click` (`cta_action=demo`)**
   「稼働しているデモが最大の証拠」という仮説の検証
5. `scroll` 90% 到達率（狭い画面）。ページが 1.6 倍長くなったことの副作用
6. **`/` と `/aichi/` の `source_page` 別内訳**。役割分離できているか

### 端末別に必ず分けて見る
今回の改修は狭い画面への効果が中心（ヘッダーCTA・SP実画面）。
端末を混ぜると効果が薄まって見える。

## 3. 実験設計（公開後）

流入が少ないため、**統計的有意差を前提にしない**。
「どれだけ早く方向の判断材料が出るか（Time to Signal）」で設計する。

| # | 仮説 | 指標 | 期待する向き | 最小シグナル | 撤退条件 |
|---|---|---|---|---|---|
| E-1 | 狭い画面の常設ヘッダーCTAが、これまで存在しなかった受け皿になる | `cta_click` `position=header` かつ端末=mobile | 0 から increase | **2週間で 3件以上**（改修前は構造上0） | 4週間で0件なら、ヘッダーCTAは効いていない。位置ではなく文言/摩擦を疑う |
| E-2 | Hero に価格を出すと、価格が合わない人が早く離脱し、残った人の質が上がる | 直帰率、`generate_lead` / セッション | 直帰率↑でも lead 率↑ | **4週間で lead 率が改修前を上回る** | 直帰率↑かつ lead 率↓なら、価格提示が早すぎる。Problem の後ろへ移す |
| E-3 | 実物の面積（PC+SP 12枚）が信用を作る | `scroll` 90% 到達率、works 到達後の `cta_click` | 到達率↑ | **works セクション以降の CTA クリックが全体の30%以上** | works 以降のクリックが 10% 未満なら、作品は説得に効いていない。件数を減らして Price を前に出す |
| E-4 | 料金と「対応しないこと」の開示が問い合わせの摩擦を下げる | `cta_click` `position=price` | price 位置が hero に次ぐ | **price 位置が全 contact クリックの15%以上** | 5% 未満なら、料金セクションは読まれても行動に繋がっていない |
| E-5 | 概算ツール（Secondary）が Primary への橋になる | `estimator_complete` → `estimate_to_contact` | 遷移率 ↑ | **完了者の20%以上が相談へ進む** | 5% 未満なら、ツールは満足で終わっており導線として機能していない |
| E-6 | FAQ が最後の不安を消す | FAQ 到達後の `generate_lead` | ↑ | **FAQ 到達セッションの lead 率が全体平均を上回る** | 下回るなら、FAQ の内容が的外れ。設問を入れ替える |
| E-7 | `/aichi/` の SP 実画面が地域流入の信用になる | `/aichi/` の `cta_click`、`generate_lead` | ↑ | **4週間で `/aichi/` 起点の lead 1件以上** | 8週間で0なら、地域ページの証拠不足以外に原因がある（流入量そのもの） |

### 判定のタイミング
- **2週間**: E-1 のみ判定（0→1 の変化なので少数で見える）
- **4週間**: E-2 / E-3 / E-4 / E-5 を判定
- **8週間**: E-6 / E-7 を判定

### 注意
- 流入が週10セッション未満の場合、**どの実験も判定しない**。
  母数不足の数字で設計を変えると、ノイズに合わせて壊すことになる。
  その場合の律速は Design ではなく Traffic であり、Growth Engine の担当。
- A/B テストは行わない。トラフィックが足りず、分割するとどちらも判定不能になる。
  **改修前後の前後比較**で見る（期間差・季節性の影響は明記して割り引く）。

## 4. 公開直後に必ず確認すること（回帰）

| # | 確認 | 方法 | NG の場合 |
|---|---|---|---|
| V-1 | `gtag` が全ページで初期化されている | DevTools で `typeof gtag === 'function'` | 即ロールバック |
| V-2 | `cta_click` に `cta_position` が入っている | GA4 DebugView で header / hero / price / final を確認 | 属性の付け漏れ。修正して再デプロイ |

**V-1〜V-5 は公開当日に実施する。** ここを飛ばすと、以降の実験がすべて無効になる。

## 5. この計画で測れないもの（正直に）

- **CLS の実ユーザー値**: ラボ計測では広い画面で 0.005〜0.026。
  実機・実回線での値は CrUX / Search Console のコアウェブバイタルでしか分からない。
  公開4週間後に確認する
- **LCP の改善有無**: 同一の本番URLに対して 176ms〜2,608ms の振れを観測しており、
  **ラボ計測では改善したと断定できない**。実ユーザー値で判定する
- **ブランド知覚の変化**: 「未来へ、遺す。」を H1 から eyebrow に降格した影響は
  行動指標では測れない。問い合わせ内容の質（価格だけの照会が増えていないか）で
  間接的に見るしかない
