### 転送量（gzip 配信での正味比較）

ローカル配信は無圧縮なので、生の合計値では比較できない。
圧縮後で数え直した。

| 内訳 | 差分 |
|---|---|
| **作品画像** | 618KB(JPEG 6枚) → **252KB(WebP 12枚)** = **−366KB** |
| 新規CSS/JS（gzip） | proto-top.css +5.0KB / proto-works.js +2.1KB / works-render.js −4.0KB |
| index.html（gzip） | 8.7KB → 12.3KB = +3.6KB |
| **Webフォント** | 715KB → **913KB** = **+198KB** |
| **正味** | **約 −160KB** |

**画像は枚数を2倍にしながら 59% 軽くなった。**

**フォントが +198KB 増えたのは実在するコスト。**
Google Fonts の Noto Serif JP は文字が増えるとサブセットの取得数が増えるため、
本文量を2倍にした分だけフォントも増えた。
現在 400/500/600/700 の4ウェイトを読んでいるので、
**2ウェイトに削れば概ね半減できる見込み**（未実施・後述）。

## PHASE 9-12 で実際に見つけて直した不具合

実画面を見なければ検出できなかったものが3件あった。

### 1. 作品が全部消えていた（重大・修正済み）
`main.js` の IntersectionObserver は**初回に存在した `.reveal` しか監視しない**。
`renderProtoWorks()` は描画後に `window.__initReveal()` を呼んでおらず、
後から差し込んだ6作品に `is-visible` が付かず、**透明のまま置き去りになっていた**。
既存 `works-render.js` は同じ理由でこれを呼んでいる。呼び出しを追加して解消。
→ コードだけ見ても、自動テストの数値だけ見ても出てこない。実画面で発見した。

### 2. 作品を大きくするための変更で、作品が小さくなっていた（修正済み）
初版は `.pwg__shots` を「PC + SP 88px」の2カラムにしていたが、
390px 幅で PC 側が **200px を割り、本番の 340px より小さくなっていた**。
狭い画面では PC を全幅にし、SP を右下に重ねる形へ変更。
さらに `.psec > .container` に幅指定を足していたため既存 `.container` の
`padding: 0 1.5rem` と二重に食い合い、**302px まで痩せていた**。幅指定を撤去。
→ 最終 **342px**（本番 340px と同等の大きさで、SP 実機表示が追加された状態）。

### 3. 行長の指定漏れ / 見出しの不自然な改行（修正済み）
- 段落に最大幅を与えておらず、Desktop の行長中央値が 63（旧指標）と広がっていた → 40em に統一
- H1 が「構成からQAまで、ひとり / で一貫して。」と語中で改行 → `em` を inline-block 化
- `min-height` はインライン要素に効かないため、本文リンクのタップ高が 19px のままだった
  → `inline-block` + `padding-block` に変更

### 4. Hero 画像の二重取得（修正済み）
`preload` で 1440w を指定していたが、srcset が実際に選ぶのは 720w だった。
preload を 720w に合わせて無駄な取得を解消。
