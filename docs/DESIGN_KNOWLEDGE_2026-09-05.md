# CASE 001 KNOWLEDGE EXTRACTION

抽出日: 2026-09-05 / 出典: CASE 001（LEGACRAFT公式サイト改装）
根拠データ: 参考15サイトの実測（`BENCHMARK_2026-09-05.md`）+ 自社の改修前後実測

**この文書は LEGACRAFT 専用の記録ではない。** 他の Industry × Goal で再利用するために、
「何が起きたか」ではなく「どの条件で成り立つか」で書く。

各パターンには **counterexample（反証）** と **do-not-use（使ってはいけない条件）** を必ず付ける。
反証を書けないパターンは、まだ知識ではなく思い込みなので採用しない。

## PATTERN-01: Conversion Surface は「常設クローム型」か「本文反復型」のどちらか

- **pattern**: 成約導線の置き方は2通りしかない。①追従ヘッダーに1つ置いて本文は空ける ②セクションの切れ目ごとにCTAを差す。**両方やらない状態が最悪**
- **context**: サービスサイト全般。特に「デザイン品質で単価を上げたい」事業
- **evidence**: 参考12サイト実測。goodpatch / anthropic / linear / smarthr は本文CTA 0〜2・空白帯82〜100%でヘッダーにCTA常設（①）。stripe 5 / freee 6・空白帯35〜56%（②）。LEGACRAFT は改修前、狭い画面でヘッダーCTAが `display:none` かつ本文CTA 2 = どちらでもなかった
- **confidence**: 高（12/12 がどちらかに分類できた）
- **counterexample**: nakagawa（EC）は本文CTA 1・空白帯99%・ヘッダーCTAなしでも成立している。**購買導線が商品カード自体**であるため、CTAという概念が別の形をとる。EC では当てはまらない
- **reuse condition**: 商品ページではなく「相談・見積・資料請求」を取るサイト
- **do-not-use**: EC / 予約が商品単位のサイト / 1画面完結のツール

## PATTERN-02: 下部固定CTAバーは、品質で選ばれるサイトでは使われていない

- **pattern**: 画面下端に固定するCTAバーは、日本のLP文法であってデザイン品質で選ばれるサイトの文法ではない
- **evidence**: 参考12サイトで採用 **0件**。下部固定要素として検出されたものは全て Cookie バナーかメニュートグルだった
- **confidence**: 中（12件は「品質・目的が近い」基準で選んだ標本であり、日本の中小企業向けLP全体の標本ではない）
- **counterexample**: 実測していないが、価格訴求型のLP・アフィリエイト系では一般的な手法。**「効かない」ではなく「価格帯の記号として逆に働く」**
- **reuse condition**: 単価を上げたい / ブランドで選ばれたい事業
- **do-not-use**: 単価が低く回転で稼ぐ事業。そこでは下部バーが正解でありうる

## PATTERN-03: 信用は「実物の面積」で作られる。文章では作られない

- **pattern**: 証拠として機能しているのは ①制作物の大きな画像 ②クライアントのロゴウォール ③顔の見える写真 のいずれか。「品質が高い」と書いているサイトは無い
- **evidence**: 200px超の画像で smarthr 46 / goodpatch 43 / nakagawa 34 / stripe 27 / baigie 24。baigie はチーム写真をHeroに使用。LEGACRAFT は改修前 TOP 6枚・`/aichi/` **0枚**（見出しで「中身をすべて公開しています」と宣言しながら）
- **confidence**: 高
- **counterexample**: anthropic は 200px超の画像 0 でも信用が成立している。**すでにブランドが確立している**場合、証拠の提示は不要になる
- **reuse condition**: 無名・実績構築段階の事業者
- **do-not-use**: ブランドが既に知られている場合。過剰な証拠提示は逆に自信の無さに見える

## PATTERN-04: 実績が作れない事業者が正当に増やせる証拠は1種類しかない

- **pattern**: 顧客の声・導入ロゴ・受注件数が無い事業者にとって、増やせる証拠は**自分が作った実物の画像と、実際に開ける稼働物**だけ。他は捏造になる
- **evidence**: CASE 001 では 6作品すべてに公開URLがあった。実サイトを撮影して PC 6枚 + SP 6枚 = 12枚に増やし、デモリンクをボタンに昇格させた。人物・オフィス・顧客の声は1つも作っていない
- **confidence**: 高（原則としての確度。効果の確度ではない）
- **counterexample**: なし。**これは効果ではなく制約**であり、反証があってはならない類のもの
- **reuse condition**: すべての実績構築段階の事業者
- **do-not-use**: 該当なし。**例外なく守る**

## PATTERN-05: 大きな H1 は、その面積に見合う情報を載せなければならない

- **pattern**: H1 が大きい参照先は、その大きさで**製品が何であるかを言い切っている**。小さい参照先は Hero の主役を写真と本文に譲っている。どちらでもなく「大きくてブランド標語だけ」は型として存在しない
- **evidence**: anthropic 61px / linear 64px / locomotive 70px はいずれも1文で製品を定義。baigie 25px / goodpatch 16px は H1 を小さくして写真に譲る。LEGACRAFT は改修前 **86px（計測群で最大）で中身は6文字**、オファー情報ゼロ
- **confidence**: 高
- **counterexample**: toraya / kaikado は H1 が無く、画像だけで成立。**すでに誰もが知っているブランド**では成立する
- **reuse condition**: 無名の事業者。5秒で「何屋か」を伝える必要がある場合
- **do-not-use**: 誰もが知っているブランド

## PATTERN-06: 作品を見せる面は明転する

- **pattern**: 暗い地に制作物のスクリーンショットを置くと作品が沈む。作品セクションだけ地を返すと解決する
- **evidence**: 参考群で作品を主役にしているサイトは例外なく明るい地（anthropic #FAF9F5 / goodpatch #F0F1F2 / baigie #F5F5F5 / basic #F4F4F4）。暗い地は linear のみで、linear が見せるのは**自社製品のUI**であって他者の制作物ではない。CASE 001 では works セクションのみ Ivory #F2EFE6 に反転
- **confidence**: 中（明転の効果そのものは前後比較で測定していない。参考群の傾向とコントラスト実測に基づく判断）
- **counterexample**: linear。ダークUIの製品を見せる場合は暗い地の方が良い
- **reuse condition**: 他者の制作物・写真を並べるポートフォリオ／実績セクション
- **do-not-use**: 見せるものがダークUIの製品そのものである場合
- **注意**: 明転部のアクセント色は再計算が必要。Gold #B08D3F は暗地で AA を満たすが、Ivory 地では **2.72** しか出ない。明地専用の濃い金（#6B5320 = 6.36）を別トークンで持つ

## PATTERN-07: 性能とデザイン品質は相関しない

- **pattern**: 「良いデザインには重さが必要」は成立しない。したがって性能は Art Direction を諦める理由にならず、**守るべき制約**として扱える
- **evidence**: 実測レンジは 0.6MB〜81.2MB、LCP 328ms〜24.4秒。最上位のデザイン品質を持つ anthropic 1.7MB / stripe 1.9MB / linear 0.6MB は最軽量帯。一方 baigie は LCP 24.4秒、locomotive は CLS 0.904
- **confidence**: 高
- **counterexample**: locomotive / igloo は重さと引き換えに体験そのものを売っている。**体験が商品である場合**は成立しない
- **reuse condition**: 体験ではなくサービスを売るサイト
- **do-not-use**: 制作会社の自己表現サイト、アワード狙い

## PATTERN-08: 全画面WebGLは受け皿ゼロと同義

- **pattern**: 全画面の3D/WebGL体験は、DOMテキストもスクロールも成約導線も持たない
- **evidence**: igloo.inc は DOM テキスト 0文字・15.7MB、bruno-simon.com は 5文字。両者とも CTA 0
- **confidence**: 高
- **counterexample**: 個人の技術誇示・採用目的なら正しい選択。bruno-simon はそれで機能している
- **reuse condition**: 該当なし（事業サイトでは採らない）
- **do-not-use**: 問い合わせ獲得が目的のサイト

## PATTERN-09: 移植したコピーは、移植元を食う

- **pattern**: 既にあるページから本文をそのまま持ってくると、同一ドメイン内で重複ページが生まれ、どちらが残るかを制御できなくなる
- **evidence**: CASE 001 で `/aichi/` の Problem / Price / FAQ を TOP に移植した結果、TOP本文の **62.8%（1,174/1,869字）が文字単位で一致**、FAQ は 7問中4問が設問文まで同一になった。`/aichi/` は唯一の地域KW受け皿（areaServed に9市）だったため、これを食う構図だった
- **confidence**: 高（文字単位の実測）
- **counterexample**: 仕様の箇条書き（プラン内容・納期）は一致していても問題ない。**書き分けるべきは散文**（回答文・ポリシー文）
- **reuse condition**: 同一ドメインに複数のランディングを持つすべての場合
- **do-not-use**: 該当なし。ただし過剰な書き分けは1人運用では維持できないので、**構造は共有し、散文だけ分ける**

## PATTERN-10: 「見出しで宣言して、実物を置かない」は最も検出しやすい欠陥

- **pattern**: `制作物は、中身をすべて公開しています` `崩れないスマホ表示` のような宣言型見出しは、直下に対応する実物があるかを機械的に照合できる
- **evidence**: `/aichi/` は当該見出しの下に 200px超の画像が0枚。TOP の「崩れないスマホ表示」も SP の実画面を1枚も持っていなかった
- **confidence**: 高
- **counterexample**: 抽象的な価値表明（「未来へ、遺す。」）は照合対象にならない。**検証可能な主張だけが対象**
- **reuse condition**: QA の定型チェックとして組み込める（宣言型見出し → 直下N pxの範囲に対応する実物があるか）
- **do-not-use**: 該当なし

## PATTERN-11: JS で描画するコンテンツは、静的にも書き出す

- **pattern**: 主要な証拠を JS 注入だけに頼ると、生HTMLから消える
- **evidence**: CASE 001 の初版は `<div id="proto-works"></div>` が空で、作品名・alt・CASE STUDY へのリンクが生HTMLに1つも無かった。同リポジトリの `works.html` は同じ内容を静的に書き出しており、**サイト内の既存規約から後退していた**
- **confidence**: 高
- **counterexample**: 装飾・演出のみの要素は静的化不要
- **reuse condition**: 検索・共有・アクセシビリティの対象になるコンテンツ
- **do-not-use**: 該当なし

## PATTERN-12: 後から差し込んだ要素は、既存の監視対象に入らない

- **pattern**: IntersectionObserver ベースの reveal 演出は、初回に存在した要素しか監視しない。動的に差し込んだ要素は透明のまま置き去りになる
- **evidence**: CASE 001 で `renderProtoWorks()` が `__initReveal()` を呼んでおらず、**6作品すべてが opacity:0 のまま画面に出なかった**。既存 `works-render.js` は同じ理由で明示的に呼んでいた
- **confidence**: 高
- **counterexample**: なし
- **reuse condition**: reveal 演出 + 動的描画を併用するすべての場合
- **do-not-use**: 該当なし
- **副産物**: この欠陥は**コード審査でも自動テストの数値でも出ず、実画面を見て初めて見つかった**。Visual QA を省略できない根拠

## PATTERN-13: 計測属性は移植の際に最も落ちやすい

- **pattern**: レンダラを差し替えると、`data-*` の計測属性が静かに消える
- **evidence**: CASE 001 で `proto-works.js` が `data-work-id` / `data-work-name` / `data-work-position` / `data-cta-action` を落としており、作品別トラッキングが GA4 に届かなくなっていた。**画面上は正常に見えるため気づけない**
- **confidence**: 高
- **counterexample**: なし
- **reuse condition**: 描画コードを置き換えるすべての場合
- **do-not-use**: 該当なし
- **対策**: 計測仕様（SSOT）を先に読み、差し替え後に属性の実在をDOMで数える

## PATTERN-14: 半透明で色を弱めると、コントラスト要件を静かに割る

- **pattern**: `opacity` でアクセント色を弱める手法は、合成後の実効コントラストを下げる。計測ツールが `opacity` を考慮しないと見逃す
- **evidence**: `.tval__num` / `.tflow__num` は accent-text `#C9A55C` に `opacity:0.85` を掛けており、合成後 **4.31**（要件 4.5）。自作の計測は `opacity` を無視して 0件と誤判定し、**axe-core が serious として検出**した
- **confidence**: 高
- **counterexample**: なし
- **reuse condition**: 半透明を使うすべての場合
- **do-not-use**: 該当なし
- **副産物**: 自作の計測を唯一の根拠にしない。**確立したツール（axe-core）と併用する**

## PATTERN-15: Webフォント差し替えは、箱を固定しても文字が動く

- **pattern**: CJK Webフォントの `display=swap` は、要素の高さを `min-height` で固定しても、**箱の中のテキストノードが動く**ため CLS が残る
- **evidence**: CASE 001 で H1 の `min-height` 固定後も広い画面で CLS 0.005〜0.026 が残り、発生源は `TEXT<phero__title>` と `TEXT<EM>` だった
- **confidence**: 高
- **counterexample**: 狭い画面では 0 だった。**行数が安定していれば起きない**
- **reuse condition**: CJK Webフォント + 可変幅の見出し
- **do-not-use**: 該当なし
- **判断**: `display=optional` にすれば 0 にできるが、初回訪問のブランド表示を犠牲にする。
  0.026 は「良好」閾値 0.1 の 26% であり、実績構築段階では**受容する**という判断をした

## 計測手法そのものから得た教訓

| # | 教訓 | 具体 |
|---|---|---|
| M-1 | **相対比較の物差しが無い状態で「異常」と判定しない** | PHASE 1 で「CTA空白帯86%は異常」と書いたが、参考群では82〜100%が標準だった。実際の差は別のところ（ヘッダーCTAの有無）にあった |
| M-2 | **自作メトリクスの単位を検算する** | 行長を「全角1文字 = 0.5em」で割っており、約2倍の値が出ていた。「行長57字で長すぎる」という指摘は誤りで、実測は36字＝適正範囲だった |
| M-3 | **半透明・アルファ合成を無視した計算は嘘を出す** | コントラスト 1.34 と報告したが、正しくは 4.09 |
| M-4 | **計測手順のタイミングが結果を作る** | スクロール直後に先頭へ戻すと、最下部の要素が「不可視」と誤判定された。1.2秒待つだけで 0 件になった |
| M-5 | **ローカル配信環境の癖を欠陥として報告しない** | 単一スレッドの `http.server` が並列取得で接続を切り、偽の console error を出していた。並列化したサーバに替えると消えた |
| M-6 | **LCP はラボ計測では判定できない** | 同一の本番URLで 176ms〜2,608ms の振れを観測した。改善の主張は実ユーザー値（CrUX）でしか裏付けられない |
